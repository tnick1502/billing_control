# Выкатка: роли и права, пул БД 5, кеш авторизации

28.09.2026 · ветка изменений: рабочая копия (не закоммичено) · план: `docs/2026-09-28_roles_and_db_pool_plan.md`

## Что меняется

| Область | Изменение |
|---|---|
| Роли | Таблица `roles`, редактор в админке (4 уровня на раздел), системная роль `admin` защищена, роль с пользователями не удаляется (API + FK в БД) |
| Права | Проверка по таблице правил `app/permissions.py`, запрет по умолчанию, зависимые права чтения, права в том же SELECT, что и сессия |
| Пользователи | Нельзя понизить/отключить себя и последнего активного админа; галочка «Активен»; выбор роли из списка |
| Пул БД | 5 соединений; при старте закрываются старые соединения своего экземпляра; серверные тайм-ауты на каждое соединение; штатное закрытие пула при остановке |
| Кеш авторизации | `AUTH_CACHE_TTL_SECONDS` (по умолчанию `0` — выключен) |
| Фронт | Меню и кнопки по правам, «Нет доступа» по прямой ссылке, стартовая страница по роли, выход на логин при отзыве сессии, обновление прав на лету; админка: вкладки «Пользователи», «Роли и доступ», «Журнал», «База данных» |
| Совместимость | У роли «Сотрудник» ровно прежние права. Сотрудник больше не видит кнопок, которые раньше давали ошибку 403 (удаление счёта, правка деталей и т.п.) |

## БД

Только добавления, данные не меняются:

- новая таблица `roles` + уникальный индекс по `lower(name)`;
- засев ролей `admin` и `employee`;
- FK `users.role → roles.code` (`ON UPDATE CASCADE ON DELETE RESTRICT`), создаётся в две фазы с `lock_timeout 5s`.

Всё выполняется автоматически при старте backend. Необязательно заранее вручную: `backend/sql/2026-09-28_roles.sql` (идемпотентен).
Откат кода на прошлую версию возможен **без** отката БД (проверено: старая версия работает на новой схеме).

## Порядок выкатки

0. **Убедиться, что подключение к БД прямое, без пулера** (PgBouncer/Odyssey, обычно порт 6432). Сейчас в `.env` порт 5432 — прямое. Если когда-нибудь появится пулер, поставьте `DB_REAP_ON_STARTUP=false` и `DB_SERVER_TIMEOUTS=false`: уборщик и сессионные `SET` рассчитаны на прямое соединение.
1. **Проверить лимит соединений** на проде (psql):
   ```sql
   SHOW server_version;
   SHOW max_connections;
   SELECT application_name, state, count(*) FROM pg_stat_activity GROUP BY 1, 2 ORDER BY 3 DESC;
   ```
   Нужно, чтобы `5 + (psql, бэкапы, прочее)` было заметно меньше `max_connections`.
2. **Бэкап** (рекомендуется перед любой выкаткой со схемой): `pg_dump` или «Скачать SQL-дамп БД» в разделе «Загрузка спецификаций».
3. **`.env` на сервере** — обязательно поменять **обе** строки (иначе backend не стартует: пул больше бюджета; `hard_start.sh` теперь проверяет это заранее и не остановит работающий сервис):
   ```env
   DB_POOL_SIZE=5
   DB_CONNECTION_BUDGET=5
   ```
   Остальные новые параметры необязательны (значения по умолчанию безопасны). По желанию:
   ```env
   APP_INSTANCE=prod
   AUTH_CACHE_TTL_SECONDS=0
   ```
4. Обновить код и перезапустить: `git pull` → `./hard_start.sh`.
5. **Проверить логи backend** (`hard_start.sh` выводит последние 100 строк):
   - `startup … db_pool_size=5 … app_name=billing_control:prod`;
   - `db_reaper: …` (найдено/не найдено старых соединений);
   - `schema_ensure: users.role — добавлен FK fk_users_role_roles` (только при первом запуске);
   - нет `ERROR`.
6. **Проверить в интерфейсе**:
   - вход под `admin` → Админ-панель → «Роли и доступ»: две роли, «Администратор» — системная;
   - «База данных»: пул `…/5`, соединений `billing_control:prod` не больше 5;
   - вход под `employee`: меню как раньше, но без «Загрузки спецификаций»; на «Деталях» нет кнопки «Добавить».
7. **Сменить пароли**: `employee` → `employee1300767`; у `admin`, если он всё ещё `admin`, — тоже.
8. Через 1–2 дня работы можно включить кеш авторизации: `AUTH_CACHE_TTL_SECONDS=30` → `./hard_start.sh`. Сравнить `duration_ms` в логах до и после.

## Особенности модели прав (осознанные решения)

- «Загрузка спецификаций: просмотр» — выгрузка всех приборов/деталей/BOM в JSON; «изменение» — импорт создаёт приборы и детали независимо от прав в этих разделах; пересборка существующих спецификаций — только «полный».
- «Месячные планы: просмотр» даёт чтение счетов (нужно странице плана), без права их менять.
- В спецификациях смена статуса версии (в т.ч. «архивная») и удаление строк — «изменение»; удаление версии — «полный». Архивация детали/прибора — «полный».

## Откат

`git checkout <прошлый коммит>` → `./hard_start.sh`. БД откатывать не нужно. Пользователи с ролями, созданными в редакторе, в старой версии получат права сотрудника (старый код знает только admin/employee) — если у роли были права уже, чем у сотрудника, перед откатом отключите таких пользователей или верните им роль `employee` осознанно.

## Что проверено

- 76 автотестов backend: правило есть у каждого эндпоинта (обход всех ~90 маршрутов, сверка с OpenAPI), пресет «Сотрудник» даёт ровно прежние права на каждом маршруте, CRUD ролей, защита админа, вытеснение кеша, гонка кеша, конфиг пула.
- Независимое ревью (отдельным агентом) и исправление найденного:
  - кеш авторизации: вытеснение теперь после коммита + «поколение» кеша — отозванный доступ не возвращается даже при параллельных запросах (воспроизведено и проверено);
  - тест покрытия маршрутов раньше фактически ничего не проверял (FastAPI 0.140 хранит роутеры обёртками) — исправлен;
  - одновременные правки одной роли и одновременное понижение двух админов сериализуются блокировкой строк (`FOR UPDATE`);
  - ключ кеша политик включает сами права — рассинхрон невозможен;
  - удалённая админом роль «Сотрудник» больше не пересоздаётся при рестарте;
  - при отсутствии активных админов при старте — `ERROR` в лог с SQL для восстановления.
- Сценарий реальной выкатки: старая версия с живыми соединениями → штатная остановка → новая версия на той же БД: старые сессии пользователей продолжают работать, права сотрудника те же, уборщику нечего закрывать (старый пул закрылся штатно).
- PostgreSQL 16, копия схемы и данных текущей версии, пользователь БД без прав суперпользователя:
  - миграция на существующей БД, на пустой БД и после ручного SQL-скрипта;
  - уборщик закрывает только свои простаивающие соединения (своя БД, своё имя), не трогает psql, dev и другие базы;
  - серверные тайм-ауты выставляются на соединение;
  - штатная остановка закрывает пул;
  - старая версия backend работает на новой схеме.
- Браузер (Chromium): меню и кнопки для админа, сотрудника и роли «Склад»; «Нет доступа» по прямой ссылке; редактор ролей; вкладка «База данных»; права, выданные на лету, применяются без перелогина; после смены пароля — выход на логин.
