# Backend — ядро приложения

FastAPI-приложение в пакете **`app/`**. Точка входа: **`app/main.py`**.

## Конфигурация

- **`app/config.py`** — `pydantic-settings`: `DATABASE_URL`, TLS к БД, `CORS_ORIGINS`, `PUBLIC_ORIGIN`, флаги сидирования `SEED_ON_STARTUP`, `FORCE_RESEED`.  
- Переменные читаются из окружения и опционально из файла **`.env`** в рабочей директории процесса.

## База данных и транзакции

- **`app/database.py`**: асинхронный engine (`asyncpg`), фабрика сессий `async_session_maker`, декларативный **`Base`**.  
- **`get_db`** (dependency для роутов): открывает сессию, отдаёт её в обработчик, при **успешном** завершении делает **`commit`**, при **любом исключении** — **`rollback`** и пробрасывает исключение дальше. Все изменения в рамках одного запроса к API — одна транзакция, если не открывать дополнительные сессии вручную.

## Жизненный цикл процесса (`lifespan` в `main.py`)

1. Создание таблиц: **`Base.metadata.create_all`** (если таблиц ещё нет).  
2. **`schema_ensure.ensure_schema`** — для PostgreSQL дополнительные `ALTER`/`CREATE IF NOT EXISTS`, чтобы существующие базы догнали модель без Alembic (в т.ч. таблица **`file_contents`** и актуальные колонки **`files`**). Ошибки отдельных DDL логируются; при сомнениях в состоянии БД лучше пересоздать схему.  
3. При **`SEED_ON_STARTUP`**: вызов **`seed_database`** из **`app/seeds/init_data.py`** и **`commit`**.  
4. **`ensure_default_users`** — если пользователей нет, создаются записи по умолчанию (см. `app/auth.py`).

## Авторизация и роли

- **`app/auth.py`**: bearer-токен в заголовке `Authorization`; токен хранится в `User.session_token`.  
- Глобальный **HTTP middleware** проверяет токен, кладёт **`request.state.user`**. Публичные пути: `/health`, `/auth/login`, документация OpenAPI и т.д.  
- **Администратор** может менять данные (POST/PATCH/DELETE не из списка исключений). **Сотрудник** — в основном чтение (`GET` и т.п.); отдельные пути могут быть расширены через `EMPLOYEE_WRITE_PATHS`.  
- Запись аудита для операций записи — через **`write_audit_log`** (отдельная сессия и коммит).

## Доменные модели

Каталог **`app/models/`**: устройства, детали, заказы, BOM, месячные планы, счета, пользователи, журнал аудита.

**Файлы и счета** (см. **`app/models/invoice.py`**):

- **`Invoice`** — реквизиты счёта; связь с файлами через **`InvoiceFile`** (составной ключ `invoice_id` + `file_id`, роль вложения).  
- **`File`** — только метаданные (имя, MIME, размер, время загрузки).  
- **`FileContent`** — одна строка на файл: **`file_id`**, колонка **`data`** (байты). Удаление **`File`** с каскадом снимает и содержимое.  
- **`MonthlyPlanPartFile`** — при необходимости связывает файлы с позициями месячного плана (та же таблица **`files`**).

## Хранение и скачивание файлов

- **`app/services/file_storage.py`**:  
  - **`save_upload_as_file`** — чтение тела **`UploadFile`**, создание **`File` + `FileContent`**, `flush`.  
  - **`save_bytes_as_file`** — то же из готовых байтов (сиды).  
  - **`delete_orphaned_files`** — для списка `file_id`: если ни **`invoice_files`**, ни **`monthly_plan_part_files`** больше не ссылаются на файл, строка **`files`** (и каскадом **`file_contents`**) удаляется.  
- **`app/api/invoices.py`**: при **`delete_invoice`** сначала собираются `file_id` по счёту, после удаления счёта и `flush` вызывается **`delete_orphaned_files`**.  
- **`app/api/files.py`**: **`GET /files/{id}/download`** — подгрузка **`File.content`**, ответ с `Content-Disposition` для скачивания.

## Создание счёта с вложением

- **`POST /invoices`** — только **`multipart/form-data`**: поля счёта + обязательное поле **`file`**.  
- В одной сессии БД: разбор и валидация форм, создание **`Invoice`**, **`flush`**, сохранение файла, связь **`InvoiceFile`**. Любая ошибка до успешного **`commit`** в **`get_db`** откатывает и счёт, и файл. Пустое тело файла → 400, без сохранения счёта.

## Остальное API

Роутеры в **`app/api/`**: устройства, детали, заказы, BOM, месячные планы, счета, файлы, статистика, auth и админка пользователей. Ошибки уникальности и внешних ключей перехватываются в **`main.py`** и превращаются в ответы 409/400 с понятным текстом.

## Сиды

**`app/seeds/init_data.py`**: заполняет базу тестовыми сущностями; для счетов подключает байты из **`app/seeds/fixtures/`**. При **`FORCE_RESEED`** выполняется усечение таблиц и повторная генерация.

## Локальный запуск (без Docker приложения)

```bash
cd backend
poetry install
poetry run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Нужен доступный PostgreSQL и **`DATABASE_URL`** с драйвером **`postgresql+asyncpg://...`**.
